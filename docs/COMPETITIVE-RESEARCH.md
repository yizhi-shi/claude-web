## 提炼出的核心需求

1. **会话优先**：打开就能看到“在跑什么”，状态必须实时（idle/running/waiting/failed）。
2. **刷新安全**：页面是视图，不是任务宿主；事件日志 + 重连回放。
3. **工具可见**：命令、参数、结果、diff 要结构化，可折叠，不刷屏。
4. **审批不绕路**：权限提示必须能定位到具体工具和参数；支持一次/会话/拒绝。
5. **历史可续**：复用本机 CLI/VSCode 的 session，不要另造一套会话。
6. **手机可用**：侧栏可收起、输入区贴底、审批按钮可点。
7. **开头简单**：干净安装、一个服务、一个数据目录、首次打开设账号。
8. **不要变成 IDE**：文件树/终端/Git/MCP 管理器是第二产品，核心先做好对话与运行状态。

## 布局结论

- **项目优先侧栏**（Kanna/ccmanager）：桌面左侧固定会话列表，移动端抽屉。
- **单一主操作**：侧栏“新建会话”只负责导航到创建面板；创建表单在 Home 右侧（桌面）/首位（手机）。聊天页不再重复放“新建”按钮。
- **聊天三段**：顶部会话状态栏、中部消息流、底部输入区；审批面板固定在输入区上方。
- **工具卡片**：默认折叠；编辑/写入显示 diff；错误自动展开；命令与输出可复制。
- **状态条**：运行中显示活动工具、耗时、后台任务；空闲时隐藏，避免噪声。

## 2026-11-24 第二轮观察

重新对照 ChatGPT / Claude / claudecodeui / Kanna 的输入区与停止交互，补了三点：

1. **输入区只保留一条底栏**：主流产品都把“附件/语音/发送”放在输入框下方同一行；本项目原来的工具栏在输入框上方、发送按钮又在最下方，视线和鼠标要来回跳。现已合并为 textarea + 单行底栏。
2. **停止必须在视线内且立即有反馈**：长任务时用户不一定看输入区底部；运行状态条新增停止按钮，点击立即进入“停止中…”，2.5 秒未生效给出强制结束。参考 claudecodeui 的 interrupt 与 Kanna 的运行状态条。
3. **语音停止要“收口”**：实时 ASR 的迟到 partial 是常见痛点。本项目在停止后丢弃 partial、只应用一次 final，并允许二次点击立即取消；这比继续渲染上游 tail 更符合“我按了结束”的预期。

## 明确不做（本期）

- 内置终端/PTY：会把“结构化控制台”退化成网页终端，安全面也更大。
- 文件编辑器/Git 面板：需求真实，但会显著扩大权限与前端复杂度。
- 插件市场/MCP 管理器：先复用本机已有配置，避免重复造管理面。
- 多 Agent 供应商：本项目定位是 **Claude Code** 的 Web 控制台；多供应商另起产品更清晰。

这些能力在 [ROADMAP.md](ROADMAP.md) 中保留，不进入 v1 核心。
